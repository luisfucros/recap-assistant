## Architecture at a glance (from the specs)

**Microservice system, monorepo.** Two independently deployable/scalable services share one library; they never call each other — all coordination is async via Postgres (+ transactional outbox), the Celery broker (Redis), Qdrant, and object storage.

- **`services/api/`** — Assistant/API service: FastAPI + LangGraph agent. Latency-sensitive, stateless, scales on replicas. Layering is load-bearing: **router → service → repository/provider** (no business logic in routers; authz + user-scoping in services/repositories).
- **`services/ingestion/`** — Ingestion pipeline: Celery workers + beat. CPU/memory-heavy; scales on worker count. Does all parse/chunk/embed/upsert work. The API's `IngestionService` only validates, stores, and writes the outbox event.
- **`libs/shared/`** — imported by both: `core`, `models`, `db` (Alembic), `repositories`, `providers`, `observability`, `prompt`, `ingestion_core`.

**Infrastructure:** PostgreSQL (source of truth + outbox), Qdrant (two collections: `document_chunks` and `long_term_memory`), Redis (Celery broker + cache + sessions), object storage (MinIO local / AWS S3 prod), Prometheus + Grafana, optional Langfuse.

## Invariants that must not be violated

These are the load-bearing rules — breaking them is a bug, not a style choice:

- **Per-user isolation everywhere.** Every relational query filters by `user_id`; **both** Qdrant collections carry `user_id` in the payload and every vector search is filtered by it. The `user_id` filter is injected **server-side from the authenticated context — never from LLM/tool arguments**. A missing filter is a hard error, not an unfiltered search.
- **Reading position drives memory.** Retrieval/summaries default to the user's read range (`page_end <= current_page`); long-term summaries are keyed to `(document_id, page_start, page_end)`. The agent confirms the page range before saving memory and asks which pages were read when prior context is missing.
- **Ingestion is outbox-protected and idempotent.** Terminal `status=indexed` + chunk insert commit in one transaction *after* Qdrant upsert; a connection error never records `indexed` or emits a wrong event. Embeddings run in `EMBED_BATCH_SIZE` batches (avoids OOM on local models).
- **Duplicate docs.** Unique `(user_id, content_sha256)`; same-user re-upload → `409 DUPLICATE_DOCUMENT`; identical content across different users is NOT deduped (isolation wins).
- **Providers are pluggable, config-selected (no code change), app runs fully-hosted or fully-local.** Embeddings/storage/web-search sit behind `Protocol`s in `libs/shared/providers`: `Embedder` (OpenAI·Voyage / HuggingFace-local), `StorageProvider` (S3/MinIO), `WebSearchProvider` (Brave / Tavily). **The LLM is a LangChain chat model built in the API service** (`services/api/api/llm.py`), *not* a shared protocol — LangGraph binds tools to and streams from it. `LLM_PROVIDER` selects Claude / OpenAI / Ollama (Ollama = `ChatOpenAI` at `OLLAMA_BASE_URL`); `build_chat_model` is the raw tool-bindable model, `build_resilient_chat_model` adds `.with_retry()` + `.with_fallbacks()` (`LLM_MAX_RETRIES`, `LLM_FALLBACK_PROVIDERS`). LangChain stays out of `shared`/ingestion.
- **Observability split:** Prometheus metrics are **always on**; Langfuse tracing is **optional** — no credentials ⇒ no-op tracer, app runs identically. Tracing is never a hard dependency.
- **No inline prompts** — all prompts resolve through the prompt registry by `name@version`.
- **HITL gates** — **consequential tools** (those reaching beyond the user's own stored data: external egress, external cost/rate-limited API, or a side effect) require user approval via LangGraph `interrupt()` + checkpointer resume. The gate is a **declared per-tool `requires_approval` flag** checked by the tool node — *not* a hard-coded list — so read-only user-scoped tools run freely and new outward-reaching tools inherit the gate. Currently gated: `web_search` and external `recommend`. (Page-range confirmation before a memory write is a separate interrupt class on the same machinery.)
- **Docs + tool-agnostic project.** Public modules/classes/functions carry docstrings (explain *why*); the repo root and every service/lib keep a runnable `README.md`; docs are updated in the same change that alters behavior. **Never reference the `.claude/` rules or skills (or their names) in any file outside this one** — write the shipped project, specs included, as if the tooling did not exist.

## Commands

- **Local stack:** `make up` / `make up-d` / `make watch` / `make down` wrap `docker compose`. Optional compose profiles: `langfuse`, `ollama`.

- **Lint/format (Python):** ruff — `ruff check --select I --fix <file>` (imports), `ruff format <file>`, `ruff check --fix <file>`. A `PostToolUse` hook runs these on every `.py` Write/Edit.
- **Migrations:** Alembic lives in `libs/shared/db/`; a dedicated one-shot **`migrate`** container runs `alembic upgrade head` and exits. **Never auto-migrate on service startup** (replicas race on `alembic_version`). Services gate on `migrate` via `depends_on: service_completed_successfully`.
- **Sync the venv:** `uv sync --all-packages` — plain `uv sync` only syncs the virtual workspace root and **prunes the members** (fastapi/langchain/shared vanish, imports/tests break). Always use `--all-packages` for dev/test.
- **Tests (pytest markers):** `uv run pytest -m unit` / `-m integration` / `-m functional`; single test `uv run pytest path/to/test_file.py::test_name`. Unit suite < 2 s (no I/O); always mock LLM/external hosted APIs. `make test-infra` starts the throwaway compose test stack.
- **Frontend:** `npm test` / `npm run <script>`.

## Gotchas

- The ruff hook in `.claude/settings.json` resolves ruff from the project-local `.venv/bin/ruff` (via `$CLAUDE_PROJECT_DIR`), falling back to `ruff` on `PATH`; if neither exists it no-ops silently. The local `.venv` is uv-managed (Python 3.13.x). If you relocate the venv or drop ruff from it, the auto-format hook stops running.
- **`ingestion-beat` must be single-instance** — running Celery beat with multiple replicas would double-enqueue the outbox relay.
