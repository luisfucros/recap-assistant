# Tasks — Recap

> Implementation roadmap broken into milestones. Each task is actionable and testable. Tests accompany every feature (three-tier: unit / integration / functional). Recurring themes: **reading position drives summaries/memory**; **LLM / embeddings / storage are pluggable** (hosted or local); **prompts are versioned in a registry**; **everything is traced (Langfuse)**; **guardrails keep the assistant on-topic and safe**; and **human-in-the-loop gates external calls and memory writes**. Checkboxes track progress.

> **Runnable at every step.** Each milestone is a **vertical slice** that leaves the project in a working state: after finishing any milestone a developer can `docker compose up`, exercise the new capability end-to-end (via the UI, an HTTP call, or the CLI), and run the test suite green. Never leave a layer half-wired across a milestone boundary — if the backend gains an endpoint, the milestone also ships the minimal way to invoke and observe it. Every milestone therefore ends with a concrete **▶ Run & verify** recipe.

Legend: **[BE]** backend · **[FE]** frontend · **[INFRA]** infra/devops · **[TEST]** dedicated test work.

## Milestone 2 — Document ingestion (async pipeline, pluggable storage & embeddings)

- [x] [BE] Models + migrations: `documents` (incl. `embed_model`, **`content_sha256`**, **unique `(user_id, content_sha256)`**, **`language` (`Language` enum)**, `status`/`format` native enums), `chunks` (incl. `page_start`/`page_end`, **`content_hash` for retrieval dedup**, denormalized `user_id`), `outbox` (partial index on the unprocessed backlog). **Autogenerated** migration against real Postgres, adjusted for explicit enum create/drop; `upgrade head` + `alembic check` clean, downgrade verified. `DocumentRepository`/`ChunkRepository` (user-scoped) + `OutboxRepository` (infra) in `libs/shared`.
- [x] [BE] Upload validation (type/size at boundary — 415/413); **compute `content_sha256`** from the uploaded bytes (bounded read, never fully buffered past the cap); store original **content-addressed** (`<user_id>/sha256/<hash>.<ext>`) via `StorageProvider`. (Content-addressing helpers in `libs/shared/ingestion_core`; true multipart streaming to S3 is a later optimization.)
- [x] [BE] **(API service)** `IngestionService.upload()`: insert `documents(pending, embed_model=active, content_sha256)` + write `outbox` `document.uploaded` event in one transaction; a known duplicate is rejected before the storage write, and a concurrent-upload race is caught on the unique constraint (`IntegrityError` → rollback → same result) — both return **`409 DUPLICATE_DOCUMENT`** with the existing id (`Location` header); otherwise the `pending` document immediately. Race-safe via the unique constraint — no app-level lock. The API does no parsing/embedding. `POST`/`GET`/`GET {id}` `/documents` routes wired (paginated list, isolation-scoped detail).
- [x] [BE] **(Ingestion service)** Outbox relay on **Celery beat**: poll pending outbox events oldest-first → dispatch a Celery task per event (`document.uploaded` → `ingest_document`) → mark processed, all in one transaction; unhandled event types are acknowledged (not left to accumulate). At-least-once delivery, safe because the task is idempotent. **Single beat instance** (multiple would double-enqueue). Event-type names are shared constants (`shared.core.events`).
- [x] [BE] `ParserFactory` + PDF parser Strategy (`pypdf`: per-page text + title/author metadata) in `libs/shared/ingestion_core`. (Chapter/section extraction left null for now — no reliable PDF structure source yet.)
- [x] [BE] **Language detection (FR-16.3):** detect the document language from parsed text via `lingua` restricted to the supported set, map to the `Language` enum, store on `documents.language` (fallback to `DEFAULT_LANGUAGE` when inconclusive); `language` included in the Qdrant chunk payload. User-overridable via `PATCH /documents/{id}`. Uses the configured (multilingual) `Embedder` so chunks embed in a shared cross-lingual space.
- [x] [BE] Structure-aware chunker (configurable size/overlap in words; records `page_start`/`page_end` + per-chunk `content_hash` + token estimate). *(Retrieval-time near-duplicate collapse by hash/score (FR-1.12) lands with the retrieval tool.)*
- [x] [BE] **Batched embed step** via active `Embedder`: chunks embedded in `EMBED_BATCH_SIZE` batches (the `Embedder` batches internally). Qdrant bootstrap creates the `document_chunks` collection with `Embedder.dim` (cosine); every payload carries `user_id`.
- [x] [BE] Celery `ingest_document` task: parse→detect language→chunk→embed→Qdrant upsert (payload w/ user_id + page metadata + language)→persist chunks→`status=indexed`; **idempotent** (re-run clears prior vectors+chunks first); transient failures retry w/ bounded exponential backoff, exhausted/permanent (parse) → `failed` + reason.
- [x] [BE] **Outbox atomicity (FR-1.7.1):** the terminal `status=indexed` + `chunks` insert + `document.indexed` outbox event commit in one transaction, only after the Qdrant upsert succeeds. A Qdrant/storage/embedding/DB connection error leaves the doc retryable (status `processing`), never `indexed`-with-missing-vectors, and never emits the event for a partial result. Vectors are re-cleared on the retry.
- [x] [BE] Ingestion **metrics** via the shared observability module: `recap_ingestion_task_seconds{task,outcome}` (duration→throughput), `recap_documents_ingested_total{outcome}`, `recap_document_chunks` histogram (chunks/doc), `recap_outbox_pending` gauge (queue depth, refreshed by the relay each tick from `OutboxRepository.count_unprocessed`). **Traces**: per-phase spans (parse/detect/chunk/embed/upsert/persist) via the optional tracer on `IngestionResources` (no-op without Langfuse). Metrics helpers unit-tested.
- [x] [BE] Re-embedding maintenance job (provider switch): `run_reembed` re-embeds one document from `chunks.text` (never re-parses), replaces its Qdrant points (stable chunk-id point ids), and updates `documents.embed_model`; `reembed_all` rebuilds the collection at the new embedder dimension then re-embeds every indexed document (system-level read, per-document writes stay user-scoped). Celery tasks `reembed_document` / `reembed_all_documents`.
- [x] [BE] `/documents` routes: upload, list (paginated), detail, **`PATCH` (language override), `DELETE` (cascade: Qdrant points + stored object + doc row → chunks via DB FK cascade)**. Deletion via `DocumentService` removes external artifacts first (idempotent), then the row last as the authority, so a partial failure is safely retryable. (A dedicated `/status` endpoint is unnecessary — detail already carries `status`.)
- [x] [FE] Library view (in the Dashboard): upload dropzone + file picker, document list with live status (polls the list while any doc is `pending`/`processing`, stops when all terminal), delete, and friendly messages for duplicate/unsupported/too-large uploads. Vitest/RTL tests (fetch mocked, incl. the poll loop with fake timers).
- [x] [TEST] **unit**: **`content_sha256`/`sha256_stream` stable across identical bytes**, content-addressed key shape + user isolation, upload boundary validation (type→415, size cap→413), scoped-SQL for the document/chunk/outbox repositories, outbox poll selects only unprocessed, `IngestionService` happy path + known-duplicate + race (`IntegrityError`→duplicate), **chunker page-boundary/overlap/ordinals + token estimate + content-hash**, **PDF parser metadata + page count + parse-error**, **language detection maps to the enum and falls back**, vector payload/point-id, ingestion metrics helpers. *(Retrieval near-duplicate collapse (FR-1.12) lands with the retrieval tool in M4.)* **integration** (done — against the `docker-compose.test.yml` stack): full pipeline vs real Postgres+Qdrant+MinIO (mock embeddings) → `indexed` with chunks persisted + vectors upserted + `document.indexed` event, idempotent re-run (replaces, doesn't duplicate), **simulated Qdrant failure mid-upsert leaves status `processing` (never `indexed`) and no `DocumentIndexed` event, then a re-run recovers**, outbox relay fetch/mark-processed, **concurrent identical uploads → exactly one row, other `DuplicateDocumentError` (unique constraint)**, **same content, different users → two independent documents**. **document deletion** removes row+chunks (DB cascade) + vectors + object vs real infra; **re-embed rebuilds the collection at the new dimension, preserves points, and updates `embed_model`**. **functional** (done, DB mocked at the boundary): **re-upload same file → `409 DUPLICATE_DOCUMENT` with existing id (`Location` header)**; invalid type → 415; oversize → 413; unauthenticated → 401; list/detail scoped; **`PATCH` language override (+ reject unsupported); `DELETE` cleans artifacts, second delete 404, auth required**. **Exit:** the ingestion service (Celery) turns uploads into searchable, page-tagged chunks independently of the API; duplicate uploads are rejected per-user (`409`) and race-safe; embeddings run in bounded batches; a connection error never records wrong status/info; provider swappable via re-embed; failures visible and retryable.

- [x] [BE] `evaluation/datasets/`: a **versioned custom dataset** of `question → {expected chunks / reference answer / expected behavior}` cases over sample documents. - [x] [BE] `evaluation/scorers/`: retrieval scorers (hit-rate / recall / MRR) and answer-quality scorers (groundedness/faithfulness, relevance, citation correctness) incl. an **LLM-as-judge** option. Done: `api/evaluation/scorers/retrieval.py` (`hit_rate`/`recall`/`mean_reciprocal_rank`, pure functions over retrieved-vs-expected chunk ids) and `api/evaluation/scorers/judge.py` (`EvaluationJudgment` — `faithfulness`/`relevance` floats in `[0,1]`, `citation_ok` bool, `reasoning` — the structured output of a new `evaluation_judge@v1` registry prompt, rendered with the case's query/retrieved-context/reference-answer/actual-answer and invoked through a cheap-tier `.with_structured_output` judge, same pattern as the guardrail/spoiler judges).
- [x] [BE] `EvaluationService`: run a dataset through retrieval + the agent, compute scores, record results to Langfuse tagged by prompt/model/embedding version. The whole run is wrapped in one `evaluation_run` tracer span tagged with the dataset name/version *and* the resolved `prompt_version`/`llm_provider`/`llm_model`/`embedding_model` (a Langfuse no-op when tracing is disabled, per the observability split) — satisfying "comparable across prompt/model/embedding versions" (FR-12.3) whether or not Langfuse is configured, since the same tags land on the persisted `EvaluationRun` row either way. ## Milestone 10 — AWS Terraform infrastructure as code

Infrastructure-as-code deployment on AWS using Terraform. The entire production stack (API, ingestion workers, Postgres, Qdrant, Redis, S3, CloudFront for the frontend) is defined declaratively; environments can be stood up repeatably, with state management, secrets handling, and monitoring integration — including the same Prometheus/Grafana dashboards and alert rules already built and provisioned locally in M9, now self-hosted on AWS rather than left as a local-only tool.

- [ ] [INFRA] **Terraform project structure**: root module + child modules for major components (`vpc`, `postgres`, `qdrant`, `redis`, `s3`, `ecs-api`, `ecs-ingestion`, `cloudfront`, `monitoring`, `security`). State backend on S3 with DynamoDB locking. Remote state sharing across modules.
- [ ] [INFRA] **VPC & networking**: private subnets for databases/cache, public subnets for ALB (API) and CloudFront (frontend). Security groups per tier (ALB, API, workers, databases). NAT gateway for outbound egress from private services.
- [ ] [INFRA] **RDS Aurora PostgreSQL** (serverless v2 for cost scaling): subnet group, parameter groups (async, connection pooling, performance insights), automated backups to S3 (retention policy), read replicas for HA, enhanced monitoring via CloudWatch.
- [ ] [INFRA] **Qdrant on ECS Fargate**: single task (replicas=1, no auto-scaling for statefulness) with task definition (memory/CPU, log routing to CloudWatch), EBS volume attached for persistent vector data (AWS now supports EBS on Fargate), service with internal ALB target group, secrets injection for admin API key. Regular snapshots of EBS volume to S3 (daily, 7-day retention) for disaster recovery. *(Note: High-availability Qdrant would require cluster mode (inter-node coordination) or switching to a managed vector DB; single-instance + backup is suitable for M10 and the current product stage, with a clear upgrade path documented for when scale demands HA.)*
- [ ] [INFRA] **Redis on ElastiCache** (cluster mode disabled, single AZ for dev / multi-AZ for prod): subnet group, parameter groups (maxmemory-policy, timeout), backup to S3, monitoring via CloudWatch.
- [ ] [INFRA] **S3 buckets** (document uploads, chat media archives, Langfuse traces optional, Terraform state): versioning + MFA-delete on production buckets, lifecycle policies (archive old media to Glacier after 90d), bucket encryption (KMS), public-access block, CloudFront origin identity (OAI) for frontend assets.
- [ ] [INFRA] **ECS Fargate for API service**: task definition (health check, resource limits, env var injection), service (desired count, deployment strategy, auto-scaling on CPU/memory/ALB request count), CloudWatch logs, IAM role + policy (S3/Qdrant/RDS/SecretsManager access). Blue-green deployments via CodeDeploy (optional for M10; basic rolling update sufficient).
- [ ] [INFRA] **ECS Fargate for ingestion workers** (Celery): task definition (CPU memory heavier than API), service with 2–4 tasks (scale target), Celery worker entrypoint. Beat service for scheduled tasks (one task, `replicas=1` hardcoded). CloudWatch logs + alarms (queue backlog, task failures).
- [ ] [INFRA] **CloudFront + S3 for frontend**: S3 bucket (static SPA files, lifecycle/versioning), CloudFront distribution (cache policies — short for `index.html`, long for static assets), OAI for S3 access, HTTPS (ACM cert), security headers in origin request policy. `npm run build` artifacts uploaded on deploy.
- [ ] [INFRA] **Application Load Balancer** (public, multi-AZ): target groups for API (health: `/api/v1/health`), listener rules (path-based or host-based if needed), stickiness for WebSocket (disabled by default; enable if needed for session affinity). Security group allows 80/443 from CloudFront + ALB.
- [ ] [INFRA] **Secrets & config management**: AWS Secrets Manager (API keys, DB passwords, JWT secrets, LLM providers, OAuth credentials); AWS Systems Manager Parameter Store (non-secret config like feature flags, region, app version). `.env` file generation via `terraform output` for local dev; Fargate tasks pull secrets at startup.
- [ ] [INFRA] **IAM roles & policies**: least-privilege per service (API reads/writes S3/Qdrant; worker reads/writes all; no service assumes human user roles). Service-linked roles for RDS/ElastiCache. Audit trail via CloudTrail.
- [ ] [INFRA] **CloudWatch monitoring**: custom dashboards (per-service metrics, ALB latency, RDS connections, Qdrant health, queue depth); log groups per service with retention (30d default, 90d prod); alarms on error rates, latency SLOs, database connections, queue stalls (→ SNS topic for paging, seeded with a no-op mock until alerting is configured). Covers AWS-native infra metrics and log aggregation — the app-level dashboards and PromQL alerting already built in M9 stay owned by Prometheus/Grafana (below), not duplicated here.

Prometheus scrapes the same `api`/`ingestion` targets already defined for local dev (`docker/prometheus/prometheus.yml`), resolved via AWS Cloud Map service discovery instead of static compose hostnames, and loads the already-committed alert rules (`docker/prometheus/alerts.yml`) unchanged — they keep firing in its own `/alerts` UI, same no-Alertmanager caveat as the local stack. - [ ] [TEST] **Terraform validation**: `terraform fmt`, `terraform validate` (syntax + variable type checking); `tflint` (best-practice linting — no hardcoded IPs, no public DBs, etc.).
- [ ] [TEST] **Workspace setup**: `dev`, `staging`, `prod` workspaces with per-env variable overrides (instance counts, backup retention, log retention, auto-scaling targets).
- [ ] [INFRA] **Zero-downtime deployment**: ALB target group draining (30s grace), rolling update strategy (25% at a time for Fargate services), blue-green optional via CodeDeploy + Lambda for instant rollback.
- [ ] [INFRA] **Disaster recovery**: automated RDS backups (7-day retention, daily snapshots to S3), Qdrant persistent volume snapshots (daily), secrets backup (readonly copy to secondary region). Runbook for regional failover (read-only replica promotion, Qdrant rebuild from snapshot).

**Exit:** the entire production infrastructure is defined as code; AWS environments are spun up from scratch via `terraform apply`; state is versioned and locked; CI/CD gates all infrastructure changes; the same Grafana dashboards and Prometheus alerts verified locally in M9 are reachable and populated on AWS.

- Type hints on all signatures/attributes; routers thin; authz + user-scoping at the service/repository layer.
- **Document as you go:** docstring every public module/class/function (explain *why*, not *what*); each service/lib keeps a runnable `README.md`; update docs in the same change that alters behavior; no commented-out code.
- **No inline prompts** — every prompt resolves through the registry by `name@version`.
- **Trace new LLM/tool/retrieval work** through the observability wrapper (best-effort, never blocks a request).
- Update tests whenever a feature is added; mock LLM/external hosted APIs; keep unit suite < 2s.
- Keep `.env.example`, `requirements.md`, `architecture.md`, and this file consistent as scope evolves.
